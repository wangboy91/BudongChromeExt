# 2026-10-07

## 排查 media-downloader 在央视 tv.cctv.com 的「下不了」问题

用户反馈：`https://tv.cctv.com/2020/10/11/VIDESNDVrdVzvu22wLLMNUEy201011.shtml` 里的视频下载不了。

### 结论：扩展其实能下，已端到端实测通过

- 页面播放的是**标准 HLS**，走 `https://dh5ws01.v.cntv.cn/asp/h5e/hls/main/0303000a/3/default/<guid>/main.m3u8?maxbr=2048&contentid=...`
  - master 里有 4 档码率：450 / 850 / 1200 / 2000（BANDWIDTH 460800 / 870400 / 1228800 / 2048000）
  - 子列表是普通 `0.ts`、`1.ts`…，**没有 `#EXT-X-KEY`，未加密**；`video/mp2t`
  - CDN 不校验 Referer；`Access-Control-Allow-Origin: *`
- 视频信息接口：`https://vdn.apps.cntv.cn/api/getHttpVideoInfo.do?pid=<guid>`，返回顶层 `hls_url` / `manifest`（含 `hls_enc_url`、`hls_h5e_url`、`hls_enc2_url`）。页面 guid 写在 HTML 里的 `var guid`。
- 播放器是 `js.player.cntv.cn/creator/vodplayer.js` + `html5player_standard_multi.js`（hls.js），`<video>` 的 src 是 `blob:https://tv.cctv.com/...`。
- 实测（headless Chrome 154 + CDP `Extensions.loadUnpacked` + 在后台 SW 里 evaluate 读 `tabMedia`）：
  - 弹窗拿到 **14 条**，其中可见 5 条全是 HLS：`main` / `2000` / `450` / `850` / `1200`；9 条 `.ts` 被 `markSegments` 正确隐藏
  - 端到端：master→自动选 2000 档→244 个分片→合并 **599.2MB** 合法 MPEG-TS（头字节 `47 40 11 10`），耗时 21.9s，`chrome.downloads` 成功

### 真实体验上的三个坑（不是 bug，但会被当成「下不了」）

1. 5 条条目名字是 `main`/`450`/`850`/`1200`/`2000`，全部标「HLS 播放列表」，没有一条叫「视频」；点 `main` 会自动挑**最高**码率 → ≈600MB。没有码率选择入口。
2. HLS 合并是**在弹窗里全内存缓冲**（`parts` 数组 + Blob，峰值堆 ≈599MB）后才交给 `chrome.downloads`。**弹窗一失焦关闭，整个下载就中断，什么都不保存。**
3. 存下来是 `.ts`，很多播放器打不开，容易被当成失败。

### 发现的真 bug（与央视无关，但影响面更大）

`manifest.json` 的 `content_scripts` 只注入了 `hook.js` 和 `content.js`，**漏了 `media-types.js`**。
而 `content.js` 第 11-12 行是：

```js
const MT = globalThis.MediaTypes;
if (!MT) return;
```

→ 内容脚本在**每个页面**上都直接 return，整个隔离世界那一层全废：
DOM 里的 `<video>` / `<source>`、`blob:` 流、`performance` 资源扫描、`hook.js` 转发过来的 blob 消息全部失效。
实测佐证：央视页面上 14 条记录**全部 `source: "network"`，一条 `blob`/`dom` 都没有**。

修法：`content.js` 那条 content_scripts 的 `js` 改成 `["media-types.js", "content.js"]`。

### 可复用的实测手法

无头 Chrome 里真跑扩展：`Extensions.loadUnpacked({path})` → 建标签页 → `Target.getTargets` 找 `background.js` 的 service_worker → `Target.attachToTarget` + `Runtime.evaluate` 读 `tabMedia`。
注意：Chrome 154 起 `--load-extension` 命令行开关默认失效，用 CDP 的 `Extensions.loadUnpacked` 更稳。

脚本放在 `%TEMP%/cctvprobe/`（probe.js ~ probe6.js）。

## 【真正的根因】用户后续补充症状：下载下来「有声音没画面」

### 结论：央视 `h5e` 变体只加密视频流，音频是明文

页面播放器实际拉的是 API 里的 **`hls_h5e_url`**（不是 `hls_url`）：
`https://dh5ws01.v.cntv.cn/asp/h5e/hls/main/0303000a/3/default/<guid>/main.m3u8?maxbr=2048&contentid=...`
（host 与 API 返回的 `dh5wswx02.v.cntv.cn` 不同，但 path 完全一致 → 确认就是 h5e 那条）

实测证据（`%TEMP%/cctvprobe/`）：

1. **h5e 的视频解不出来**：`ffmpeg -i sample2.ts -ss 60 -frames:v 1` → 灰底雪花（`error while decoding MB…` / `non-existing SPS 0` 刷屏）
2. **非 h5e 的同名资源完全正常**：`https://newcntv.qcloudcdn.com/asp/hls/450/.../0.ts` 拼起来抽帧 → **清晰的 CCTV13 采访画面**
3. **音频是明文**：把 h5e 与 plain 两条音轨都转成 8k 单声道 PCM，按 100ms 算 RMS 包络，**相关系数 = 1.000**，逐点数值吻合（317/319、2990/2988、3261/3259）→ 音频没被加密

所以：**h5e = 视频 ES 加密、音频明文**；播放器在 JS 里解密视频后喂 MSE，所以浏览器能播；扩展只是原样抓分片拼接，拿到的就是「加密视频 + 明文音频」→ 有声音没画面。

### 可用解法（明文流）

`https://vdn.apps.cntv.cn/api/getHttpVideoInfo.do?pid=<guid>` 返回的顶层 `hls_url` 就是明文流：
`https://newcntv.qcloudcdn.com/asp/hls/main/0303000a/3/default/<guid>/main.m3u8?maxbr=2048`
实测不需要 Referer，ffmpeg 直接 `-c copy` 即可。

### 要根治，扩展需要新增「URL 改写」钩子

`platforms.js` 目前只有 `match / extract / fromTitle / filename` 四个钩子，**没有改写媒体地址的能力**。
央视适配器需要：从 `/asp/h5e/hls/.../3/default/<guid>/...` 抠出 guid → 调 `getHttpVideoInfo.do?pid=<guid>` → 取 `hls_url` 替换。

同时别忘了 manifest 漏 `media-types.js` 那个 bug（见上）。
