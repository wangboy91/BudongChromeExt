# 2026-10-01

## 新增扩展：audio-downloader（网页音频嗅探下载）

在 `BudongChromeExt` 仓库新增第二个扩展 `audio-downloader/`，目标是「任意网站通用音频下载」。

### 关键决策
- 采用 **网络嗅探 + DOM 扫描 + 页面钩子** 三通道互补，而不是只扫 DOM：
  - `webRequest.onBeforeRequest`：按 URL 后缀先认
  - `webRequest.onHeadersReceived`（带 `responseHeaders`）：按 content-type / content-disposition / content-length 精确判定，覆盖**没有后缀的签名直链**
  - `content.js`（隔离世界）：扫 `<audio>/<video>/<source>`、`<a href>`、`performance` 资源
  - `hook.js`（`world: "MAIN"`）：包装 `URL.createObjectURL` 抓 blob 内存流
- 判定优先级写死在 `media-types.js` 的 `describe()`：服务端 MIME → HTML 排除 → URL 后缀 → content-disposition → 「请求类型 = media」兜底。最后一条是关键，签名直链常返回 `application/octet-stream`。
- `.ts` 要特殊处理：既是 MPEG-TS 又是 TypeScript，靠 mime 区分（`application/javascript` 等直接排除）。
- HLS 分片（`.ts/.m4s/.aac/.mp4`）会被 `markSegments()` 标 `hidden` 折叠，避免刷屏；弹窗有「显示流分片」开关。
- `blob:` 下载路径：`chrome.scripting.executeScript({world:"MAIN"})` 在页面世界读成 data URL（>32MB 退回页面原生 anchor 保存）。
- HLS 合并放在 **popup** 里做（主列表选最高码率纯音频轨 → 并发 4 拉分片 → AES-128 解密 → 拼 Blob → object URL 下载）。
- service worker 会被回收，所以列表用 `chrome.storage.session` 缓存；写盘只覆盖 dirty 的 tabId，避免抹掉未 hydrate 的其他标签页。

### 实测目标站点
`mossland.studio/voice/library` 是 Nuxt SPA，音色通过 REST 接口返回直链（`audioUrl` / `audioSampleUrl`），由 `<audio>` 播放 —— 正好是嗅探方案的覆盖场景。

### 坑与注意
- 后台通知弹窗做了 400ms 尾沿节流 + 可见数量变化才更新角标，否则 HLS 播放时会被分片 upsert 刷爆。
- 弹窗在 `state.pending > 0`（单个下载进行中）时跳过重渲染，避免把「处理中…」按钮重置。
- 图标用纯标准库 Python 生成：`audio-downloader/tools/make-icons.py`。

## 追加：预览升级为播放器面板

原实现用 `new Audio()` 静默试听，视频条目点了只有声音没画面。改成列表上方的 `#preview` 面板：
- 音频 → 原生 `<audio controls>`（可拖进度/调音量），视频 → 内嵌 `<video controls>`（max-height 140px）。
- 面板右上角 `↗` 用 `chrome.tabs.create` 丢到新标签页看全尺寸。
- 打开预览时给 `body` 加 `.preview-open`，把 `.list` 的 `max-height` 从 330px 收到 150px，保证弹窗总高不超 600px。
- `state.audio` 改名 `state.player`；预览元素的 `error`/`ended` 回调**用元素身份校验**（`state.player !== player` 就返回），否则 `stopPreview()` 里 `removeAttribute("src") + load()` 触发的异步 error 会误杀下一次预览。
- `blob:`/HLS/DASH 仍不可预览，按钮置灰并用 `previewHint()` 说明原因。

## 追加：改名「音视频下载」+ 平台适配层

用户要求：通用嗅探打底，**只对单平台做命名/文案优化**，没适配的维持现状；工具改名「音视频下载」。

- 目录 `audio-downloader/` → **`media-downloader/`**（manifest name/version 0.2.0、popup 标题、根 README 表格同步）。旧目录加载过的话要在 `chrome://extensions` 里移除后重载。
- 图标从音符改成播放三角（`tools/make-icons.py` 里的 `PLAY` 多边形）。
- 新增 **`platforms.js`**：适配器注册表 `{ id, label, match(host,url), extract?, fromTitle?, filename(ctx)? }`。
  - `extract` 用 `chrome.scripting.executeScript({ world: "MAIN" })` 注入执行，**必须自包含**（辅助函数写在函数体内），已用 `new Function('return '+src)()` 在无闭包环境实测通过。
  - `filename(ctx)` 只返回**不含扩展名的基名**，扩展名由弹窗统一补 —— 这样长标题截断不会切掉后缀。
  - 已实现：抖音（RENDER_DATA + React fiber 拿作者/文案/作品ID）、B站（`window.__INITIAL_STATE__`）、网易云 & QQ音乐（解析 `<title>`，无需注入）。
  - 任何一步失败都只是「没有增强」，条目本身照常，退回通用命名 `标题-站点-短哈希.ext`。
- 弹窗新增文案卡（`#meta`），含「复制文案」；`copyUrl` 重构为 `copyText(text, label)`。
- **布局重构**：`.app` 改成 `max-height:600px` 的 flex 列，`.results`/`.list` 用 `flex:1 1 auto; min-height:0` 自动让位，去掉了原来的 `body.preview-open .list{max-height}` hack —— 现在文案卡和预览面板同时出现也不会溢出。

## 修 bug：预览「播放不了」

用户截图反馈：状态栏显示「预览已加载，点播放器上的播放键开始」，但预览面板消失了。

**根因 1（竞态）**：媒体加载失败时 `error` 事件先触发 → `stopPreview()` 关掉面板并提示失败；随后 `play()` 的 promise 才 reject → `.catch` 把状态**覆盖**成「预览已加载…」。用户看到的是"面板没了 + 一句误导的话"。
→ 修法：`.catch` 里也加 `if (state.player !== player) return;` 身份校验，失败路径不再被覆盖。

**根因 2（真放不了）**：弹窗是 `chrome-extension://` 源，抖音 CDN 会校验 Referer 而拒绝加载。
→ 新增**页面内预览兜底**：`showInPagePlayer(url, isVideo, title)` 走 `executeScript({world:"MAIN"})`，在页面右下角挂一个带关闭按钮的播放器。页面自身来源/Cookie/Referer 都对，能正常加载。函数同样自包含，已实测可独立重建。

**顺带修的展示问题**：抖音首页（`douyin.com/`、`/discover`）没有具体作品，原来会把 `document.title`（"抖音精选电脑版"）和 `meta description` 当成作者/文案显示。现在 `douyinExtract` 在 `!workId` 时直接返回空对象，`renderMeta` 也要求作者/作品ID/文案至少有一个才显示卡片。

**命名可读性**：新增不透明 ID 判断 —— URL 末段是 ≥24 位纯字母数字（如抖音 CDN 的 `oMM75n8KBQRXqXw...`）时不用它当标题，退回页面标题，于是文件名从 `oMM75n8...mp4` 变成 `抖音精选电脑版-v26-web.douyinvod.com-xxxxxx.mp4`。
