# 2026-10-08

## media-downloader：修好内容脚本注入 bug + 新增央视网 / YouTube 适配（v0.3.1）

### 修掉的真实 bug

- `manifest.json` 的 `content_scripts` 漏了 `media-types.js`，而 `content.js` 第一行就是
  `const MT = globalThis.MediaTypes; if (!MT) return;` —— 内容脚本**在所有站点上都没跑起来**，
  DOM 扫描 / blob 钩子 / performance 扫描全部失效。补上 `"media-types.js"` 后恢复。

### 新增适配（`platforms.js`）

- **央视网**：`/asp/h5e/` 流只加密视频（音频明文），直接拼分片会得到「有声音没画面」。
  适配器从地址取 `guid` → 调 `vdn.apps.cntv.cn/api/getHttpVideoInfo.do` 拿**明文** `hls_url` →
  逐码率用 `Range: bytes=0-0` 探测，把「字节数与更低码率完全相同」的档位丢掉 → 用真实档位替换列表条目。
  实测：`[面对面]刘秀祥：奋斗的力量 640x360`，244 个分片合并成 261 MB。
- **YouTube**：网页版走 SABR，页面自己没有可下载的 GET 直链（播放器只往 `videoplayback?sabr=1` 发 POST）。
  改在**页面世界**调 innertube `player` 接口（ANDROID 客户端）拿直链。

### YouTube 的关键结论（踩坑记录）

- `chrome.downloads` 下不了自适应流：googlevideo 既要求 `Range` 请求头，又要求请求来自
  `youtube.com` 这个源。扩展源（`chrome-extension://`）→ 403；带 `Range` 但无 `Origin` → 403。
- **可行解**：注入页面世界（`world: "MAIN"`）带 `Range` 取回 → `Blob` → 页面 `<a download="名字">` 落盘。
  实测两条流都能落盘且**文件名正确**（`chrome.downloads` 下载跨源 blob 会丢掉自定义文件名，
  只能用 `<a download>`）。
- 渐进式 itag 18 带 `ratebypass`，可以直接交给 `chrome.downloads`（实测 146 MB 完整落盘）。
- 高清自适应轨受服务端风控：同一地址请求量偏大就 403。**重试 3 次仍失败则自动退回 360p 单文件**
  并在状态栏说明（`runDownload` 里的 muxed 回退分支）。
- 弹窗里 `chrome.downloads.download({filename})` 在 **CDP `Browser.setDownloadBehavior`** 下会被忽略
  （文件名退化成 URL 名 / blob UUID）。这不是扩展的 bug —— 用 profile 偏好设下载目录就正常。
  **以后写验证脚本要这么做，别用 CDP 的下载行为。**

### 架构约定（新增）

- `extract()` 返回的 `streams` 会被追加进列表，条目可带 `pageDownload: true`，
  表示「必须由页面世界带 Range 取回」（见 `popup.js` 的 `pageFetchAndSave` / `downloadViaPage`）。
- 下载进度走 `window.postMessage({__mediaDownloaderProgress})` → `content.js` 转发
  `chrome.runtime.sendMessage({type:"download-progress"})` → 弹窗 `applyDownloadProgress()`。
- 适配器可选的钩子：`canResolve` / `resolve` / `hideItem` / `cacheKey` / `cacheMs`。
